# NXR 卡片图片命名

独立的本地图片处理工具，提供网页和 macOS / Windows 桌面版。识别卡背二维码中的 NXR 证书号，将背面与排序中的前一张正面配成一组，生成 `证书号_A.webp` 和 `证书号_B.webp`。JPG/PNG 自动转为原始尺寸的无损 WebP，已有有效静态 WebP 保留原字节。

该目录具有独立的静态运行与浏览器文件权限边界，不依赖 Flask、Java、MySQL 或后台登录。源码维护在现有 `nxr_platform` 下；使用专属发布器，不参与主站和后台的发布流程。

## 桌面版 0.2.1

沿用网页界面，内置 Electron、二维码识别、OCR 模型和 WebP 编码器。双击即可运行，不需要 Node.js、浏览器、后台服务或网络连接。照片通过系统文件夹选择器授权，继续使用同一套备份、校验和恢复逻辑。二维码为准，文字仅在后台静默参考。

0.2.1 将普通二维码扫描改为最多两张并行，低资源设备使用一个工作线程；任务完成先后不改变原图顺序或 A/B 配对。单张超时和线程异常不会中断另一张，停止时同时取消运行和排队任务。深度补扫仍按倒序逐张执行，成功配对后跳过对应正图；扫描区域、二维码冲突校验和文字参考规则保持一致。

- macOS 13 或更新版本：解压后打开 `NXR Photo Renamer.app`，可拖入“应用程序”；universal 包包含 Apple Silicon 和 Intel 两种架构。
- Windows x64：完整解压便携包，打开 `NXR-Photo-Renamer-portable/NXR Photo Renamer.exe`。请保留同目录的运行资源，不能只复制 EXE。
- 当前包没有商业代码签名及 Apple 公证；macOS 使用本机临时签名校验完整性。系统可能提示来源未经验证。
- 首次打开选择照片文件夹，后续操作与下方“使用”一致。转换支持最多两个独立工作线程，没有固定时间截止，可点击“停止处理”；有未完成记录时可恢复原图。处理中关闭窗口会再次确认。

桌面资源通过 `nxr://app/` 从安装包读取，没有本地 HTTP 服务、远程页面或图片上传接口。窗口启用沙箱、上下文隔离，页面没有 Node.js 权限；系统文件权限仅授予用户选择的目录。HTTP/HTTPS 请求和外部导航均被阻止。

```bash

npm run desktop                         # 构建并运行桌面界面
npm run test:desktop                    # Electron 中的离线文件流程测试
npm run package:desktop -- --platform darwin --arch universal
```

macOS 包须在 Mac 上构建和临时签名；Windows 包支持跨平台生成，GitHub Actions 另在 Windows 上构建并启动实际 EXE 验证。输出位于 `release/<版本>/<平台-架构>/`，包含应用、ZIP、逐文件清单及 SHA-256。相同输出存在时脚本拒绝覆盖。打包只从静态构建、两个桌面宿主文件和最小运行清单创建 staging，核验最终 ASAR 与 ZIP；不包含照片、数据库、源码依赖、测试目录或任何 `.PhoenixBrain`。

自动桌面测试使用隔离 OPFS 合成图片，验证二维码、WebP、恢复、离线资源和关闭保护；系统原生文件夹选择器另需桌面验收，不能以 OPFS 测试替代。桌面更新与网页部署相互独立，本次 0.2.1 桌面更新不更新下述线上静态版本。

## 使用

1. 点击“选择照片文件夹”，授权读写。仅处理当前层的 JPG、JPEG、PNG、WebP；子目录和其他文件不参与。
2. 点击“开始识别”。照片按原文件名自然排序，并用确定性的规则处理数字和大小写排序相同的名称。普通识别完成后，未配对且未识别的图片会自动深度补扫一次，无需另点按钮；每张补扫最多约 50 秒，可随时停止。已有配对和取消勾选状态保留。
3. 每张识别到唯一有效证书号的图片直接作为背面 B；按自然排序紧挨在它前面的图片直接作为正面 A。前一张的识别结果不参与判断，即使它识别失败或也含二维码，仍按这个顺序生成一组。同一文件不会被两组重复使用。
4. “命名预览”中的证书号、A 图和 B 图均为只读固定结果。点击“待检查”可直接查看未配对原图、放大并切换上一张或下一张；也可点击左侧任意图片查看。确认未识别图片是背面时，用“人工录入”填证书号，核对其前一张正面，再加入预览。已有二维码证号优先，不允许人工改成其他证号；无二维码时文字参考不会直接生成配对。不需要的组可取消勾选或移除，人工录入组在重新识别后仍保留。第一张图片没有前图、多个二维码未确认、重复证书号或目标名冲突时不会直接执行。
5. 点击“执行改名”，核对原名与 WebP 目标名清单，再确认。转换、原图备份与校验均在本机完成。最多同时转换两张，低资源设备自动使用单线程；可点击“停止处理”，再通过改名记录恢复。
6. 同目录会保存隐藏的 `.nxr-rename-*.json` 记录及 `.nxr-originals-*` 原图备份目录。重新选择该目录后，可在“改名记录”中恢复原名称、原格式和原字节。请同时保留记录与备份，恢复完成后会清理本次已核验的备份。

二维码接受 `http(s)://nxrgrading.com/card/证书号`、对应 `www` 地址、没有协议前缀的 `nxrgrading.com/card/证书号`，以及 `/card/证书号`。证书号保留原大小写，仅允许 1–64 位 ASCII 字母数字。二维码内容仅解析，不自动访问链接。当前 Python 后台的文件夹导入要求 10 位数字证号；Java 后台另支持历史字母数字证号。

浏览器不支持目录写入、或只想先检查图片时，可使用“只读预览”。页面不再展示“导出清单”入口；执行改名前仍显示原名与目标名供确认。

## 本地处理与文件保护

- 二维码由本地打包的 jsQR 在 Web Worker 中识别，支持旋转、倒色和高分辨率分块。普通扫描会对低对比图片追加增强；深度补扫使用不同缩放尺度、3×3 重叠区域、更细滑窗、对比度拉伸和局部阈值。增强只作用于内存中的识别像素，不改变原文件和 WebP 输出。多证号仍禁止自动配对；超时且冲突校验未完成的单证号会标记为需要检查。图片及二维码不上传；资源均由工具所在站点提供，没有外部 CDN 或远端处理 API。
- 标签文字在浏览器后台识别，只作为二维码的静默参考。文字差异、识别失败或格式异常不会覆盖二维码、阻断命名或增加待检查项；无有效二维码时仍需人工确认。证书号保留前导零和大小写，拒绝路径、非法字符和猜测性字母数字替换。
- WebP 使用固定版本 `@jsquash/webp@1.5.0` 的 libwebp WASM 编码器，设置 `lossless=1`、`near_lossless=100` 和 `exact=1`。同时回读验证编码前后的 RGBA，以及浏览器显示前后的 RGBA，均须逐像素一致。无损以浏览器解码显示的像素为基准；透明像素做与浏览器显示相符的预乘颜色归一化，保留原始分辨率和显示方向。原文件的 EXIF、ICC 等元数据在原图备份中保留，转换结果不是原压缩文件的字节复制。已有 WebP 直接校验并保留，不再重编码。
- 单张识别上限为 40 MB、1.2 亿像素；无损转换上限为 24 MiB 输入和输出、4000 万像素、单边 16383 像素。转换没有固定时间截止，编码期间可主动停止。超过尺寸或体积限制会停止并保留原图，不自动降低质量或缩图。动态 WebP/APNG/GIF 不转换，避免丢失帧。
- Chrome / Edge 必须在安全上下文中使用；本地开发使用上述回环地址。普通远程 HTTP、Safari、Firefox 不承诺原目录写入。
- 文件处理采用“备份原图 → 无损转换 → 写入新名称 → SHA-256 校验 → 移除旧名称”。所有目标均核验成功后才开始移除旧文件，删除前再次核对原图、备份和输出。文件时间与部分文件系统元数据可能变化，旧文件不会进入回收站。
- 备份使用 `.nxr-source` 专用扩展名，不会被后台卡图导入规则当作图片重复录入。恢复从备份取回原字节，不把 WebP 再编码成 JPEG。旧版仅改名的恢复记录继续可用。
- 写入前校验原始大小、修改时间和 SHA-256。目标同名、仅大小写不同的占用、重复证书号或重复使用同一照片都会被拦截。源图和目标在移除旧文件前会再次核对。
- 恢复记录必须先写入并回读成功，工具才开始处理图片。中断后先检查目录和记录，再恢复；已被其他软件修改的图片、损坏记录或被占用的原名称不会被覆盖或删除。发生校验冲突时可能保留额外副本，需要人工检查。
- 同一站点的多个工具页面通过 Web Locks 避免同时写入。浏览器文件接口没有“独占创建目标名称”的完整原子保证，无法阻止其他应用在两个检查之间改变目录。执行和恢复期间不要用其他软件修改该文件夹。
- 图片扫描不处理子文件夹、数据库或其他扩展名；只维护本次生成的专用备份目录，不自动清理用户文件或历史记录。

## 结构与复用

- `src/App.vue`：文件夹授权、预览、扫描进度、自动顺序命名与确认操作。
- `src/lib/pairing.ts`：自然排序、证书链接解析、自动配对和冲突校验。
- `src/qr.worker.ts` 与 `src/lib/scanner.ts`：本地二维码识别及工作线程生命周期。
- `src/webp.worker.ts` 与 `src/lib/webp-converter.ts`：无损 WebP 编码、像素校验和独立工作线程内存释放。
- `src/lib/file-operations.ts`：安全改名、持久化操作记录和恢复。
- `tests/`：纯逻辑测试、文件系统故障注入和浏览器交互测试。
- `desktop/`：离线桌面宿主与资源访问规则，不复制页面或文件处理代码。
- `scripts/package-desktop.mjs`、`scripts/audit-desktop.mjs`：桌面打包与成品成员核验。

已检查当前仓库安装的 Phoenix Vue 组件包 `frontend.vue3.component-gallery@0.11.1` 中的文件选择与媒体组件。其文件选择控件提供只读 `File[]`，不覆盖本工具所需的目录读写句柄、改名与恢复协议；因此采用一份原生目录适配和任务页面，没有复制组件库或引入相邻后台的运行依赖。本次为一个消费页面，没有提交组件需求或其他外部反馈。
