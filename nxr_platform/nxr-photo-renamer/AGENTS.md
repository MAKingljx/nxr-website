# NXR Photo Renamer — 独立小项目

本工具作为独立静态网页维护。源码、依赖、测试、构建、发布版本与回滚记录归本目录管理；不集成进 Python 后台，不依赖业务数据库。

## 生产隔离约束

用户于 2026-09-06 明确要求：部署和维护必须避免影响现有生产系统，不得发生文件、路径、端口或配置冲突。

- 不覆盖、同步或修改 `/root/nxr_website` 内的应用文件、图片和 `Data/`，不执行整个 NXR 仓库的 pull、rsync 或部署脚本。
- 不停止或重启现网 Python 主站和管理后台，不占用其 8080/8081 端口，不改变 Flask/Java 流量切换和定时同步。
- 只发布经过审计的本工具静态构建产物；使用专属发布目录、版本指针和配置文件，不上传源码、测试图片、依赖缓存、凭据或任何层级的 `.PhoenixBrain`。
- 发布前核实目标主机、目录、URL 前缀、端口和 Nginx 配置。遇到同名已有内容或未确认的所有权必须停止相关写入，不自动覆盖或清空。
- 必须先记录现网主站、管理后台、相关进程和配置基线。只允许为该工具增加最小范围的静态入口，保留既有路由、代理与 TLS 配置。
- 如需共享 Nginx，修改前保存可恢复配置，确认配置未被并发改动，先通过 `nginx -t` 才可平滑 reload；不得 restart Nginx。失败时只回滚本工具的新增内容，不能覆盖别的任务的并发变更。
- 上线后验证工具页面、静态资源、Web Worker、HTTPS 安全上下文，并分别复核现网主站、管理后台及其进程。以实际验证结果说明影响，不把计划当作“零影响”的证明。
- 后续更新只切换该工具自己的发布版本。保留最近两个已验证可恢复的历史版本，不能清理其他项目的备份。

图片识别和改名始终在用户浏览器本地执行。服务器只提供静态网页，不接收照片、不提供文件改名 API。
