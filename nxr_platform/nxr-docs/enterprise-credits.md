# 企业统一积分额度

企业送评使用一个 `PTS` 积分余额。客户付款和订单报价仍保留实际币种，充值与送评付款按平台配置折算积分；企业额度不提供透支，也不改变子代理向自己客户收款的业务边界。

## 设置与默认值

平台入口为「系统设置 → 企业额度设置」，路由 `/system/enterprise-credit`，权限为 `nxr:credit:config`。子代理不能修改全局比例或汇率。

- 初始比例为 **1 CNY = 1 PTS**；人民币固定启用，人民币对人民币的汇率固定为 1。
- 支持 CNY、USD、EUR、GBP、HKD、JPY、CAD、AUD、SGD。八种外币初始均未配置汇率、未启用，不使用预设或自动获取的市场汇率。
- 平台分别填写「每 1 单位货币折合人民币」并启用所需币种。未配置或停用的币种不能生成新的积分报价。
- 积分比例和汇率必须大于 0、不超过 1,000,000,000，最多 8 位小数。外币停用时可以不填写汇率。

计算方式为：

```text
积分 = 原币金额 × 每单位原币折合人民币 × 每人民币积分
```

后端使用 `BigDecimal` 完成乘法，最终积分按 `HALF_UP` 保留 2 位小数。金额必须符合原币精度：JPY 为整数，其他支持币种最多 2 位小数。折算后不足 0.01 积分或超出支持范围的金额会被拒绝。

设置使用明确的保存操作，不自动保存。每次保存携带读取时的 `expectedVersion`；设置被其他人修改时返回冲突，页面保留当前输入，重新加载后才能继续保存。设置调整只作用于后续报价，不重估已有积分余额或已保存的交易快照。

## 充值、付款与退款

| 操作 | 积分处理 |
| --- | --- |
| 新建充值申请 | 核对报价版本，保存原币金额、汇率、积分比例和积分数快照；申请仍为待核款，不增加可用额度。 |
| 平台确认收款 | 按申请保存的快照入账，核验支付流水号，防止同一笔收款重复入账。 |
| 送评订单付款 | 读取服务端积分报价；提交报价版本和确认的积分数。订单、应收金额、付款条件或报价发生变化时拒绝扣款。 |
| 成功扣款 | 从企业 PTS 余额扣除报价积分，保存订单积分快照及流水；不足额时不允许透支。 |
| 积分付款退款 | 按原扣款记录的积分数退回原钱包，不按退款时的汇率重新计算。重复退款不会再次入账。 |

预览报价本身不锁定资金，也不代表已付款。新充值申请创建、订单实际扣款或历史待核款申请明确确认折算时，才保存相应交易快照。付款仍受原有订单受理、条款确认、订单状态和支付渠道冲突检查约束。

迁移前已经使用货币钱包支付的订单，退款仍退回原币钱包。此类历史余额继续进入待转换余额，避免把原币金额直接当作积分。

## 历史余额与待核款申请

旧货币钱包及其流水保留。升级和服务启动均不会自动清零、合并或折算历史余额。

具有 `nxr:customer:finance` 权限的平台财务可以在企业额度页执行以下操作：

1. 预览该企业全部非零历史币种余额及折算后的积分；涉及币种必须已有可用汇率。
2. 核对余额、积分和报价版本，填写必填转换备注，再明确确认转换。
3. 服务端重新核对版本与余额，在同一事务内将所列原币余额清零、增加对应 PTS，并写入来源扣减、积分增加流水及折算快照。

提交使用幂等请求键。相同请求重试返回已完成的转换结果；余额、报价版本或请求内容变化时要求重新核对，不能按旧预览继续转换。历史流水保持不变，新转换另记流水。

升级前尚未核款的充值申请没有积分快照，不能直接按货币金额增加积分。平台先核对并确认当前折算报价，再执行原有收款审核；确认折算本身不会充值。子代理不能批准自己的充值或执行历史余额转换。

## 金额接口契约

积分设置、报价、余额、转换结果和钱包流水中的金额字段以 **JSON 小数字符串**返回。调用方应保留字符串精度，在确认报价、付款或转换时原样提交，不经过 JavaScript `Number` 再回传。前端设置输入也保留最多 8 位小数的文本。兼容类型可以接收旧接口数值，但不能据此把新接口的小数字符串转换为浮点数。

后台接口位于 `/api/admin/enterprise-credit`，响应数据在 `AjaxResult.data` 中：

| 路径与方法 | 用途 |
| --- | --- |
| `GET /settings`、`PUT /settings` | 读取、保存全局设置。 |
| `GET /companies/{id}` | 企业 PTS 余额、比例、汇率及历史币种余额。 |
| `POST /companies/{id}/quote` | 为指定金额生成当前积分报价。 |
| `POST /companies/{id}/conversion-preview` | 历史余额转换预览。 |
| `POST /companies/{id}/convert` | 确认转换，提交 `expectedVersion`、原币余额、`idempotencyKey` 和必填 `note`。 |
| `POST /companies/{id}/recharges/{rechargeId}/quote` | 为历史待核款充值确认并保存积分报价。 |

子代理及客户接口返回原始 DTO，企业身份分别来自绑定企业范围或当前客户会话。平台财务接口仍执行平台角色检查；拥有企业绑定的子代理不能通过传入其他企业 ID 越权操作。

## 迁移与上线边界

本功能必须在启用新后端前执行 `nxr-sql/ruoyi/26_nxr_enterprise_credit.sql`。已有系统应在核对当前迁移进度后增量执行，不重跑初始化脚本，也不依赖运行时自动补表。

迁移 26 新增四张表：`enterprise_credit_config`、`enterprise_credit_rate`、`enterprise_credit_snapshot`、`enterprise_credit_conversion`，写入默认人民币设置和停用外币配置，并增加企业额度设置菜单及管理员菜单关联。迁移不转换旧钱包、不更改原订单价格、不写入真实充值或付款。

生产执行前必须核对实际 Java 运行库和发布版本，说明准确表、菜单及配置改动，验证可恢复备份，并获得当前任务的明确生产数据确认。代码发布授权不自动授权真实余额转换、充值核款或修改生产汇率；这些操作应按明确确认的对象和范围执行。Python 的 `Data/`、支付渠道凭据及其他系统数据库不在本迁移范围。

回滚前先核对是否已产生积分交易。不得为退回旧应用删除新表、覆盖业务库或抹除积分流水；已有积分交易的环境需要能识别 PTS 和交易快照的兼容版本。生产发布状态以实际服务、数据库迁移和线上验收结果为准，本文不代表已上线。
